# 采购询源与比价工作流

## 1. 采购需求理解

将自然语言转换为采购需求卡，包括产品、数量、必须参数、偏好参数、预算、MOQ、交期、收货地、税票、定制和供应商要求。需求状态分为：

- `DRAFT`：信息不足，尚未评估。
- `NEEDS_CLARIFICATION`：存在阻断字段，需要补问。
- `SEARCH_READY`：可制定搜索策略。
- `COMPARISON_READY`：候选数据足以进行正式比价。
- `RFQ_READY`：可生成统一询价内容。

## 2. Query Planner

把需求扩展为“平台 × 搜索词 × 筛选条件”。搜索词需要覆盖产品同义词、品类词、工厂或定制意图、关键材质与规格，并保留不同语言的查询变体。

## 3. 平台 Adapter 与候选池

每个平台适配器输出统一候选结构。后续候选 Schema 至少覆盖商品标题、链接、供应商、价格区间、MOQ、交期、运费、税票、规格、定制能力、供应商类型、认证、销量和评价。

数据获取按能力分级：公开搜索、公开商品页、官方或合规接口、需登录或人工补充。获取不到的数据不得推断。

## 4. 商品归一化与匹配

逐项比较核心规格、定制、MOQ 和交付要求。建议匹配等级：

- ≥90%：强匹配
- 80%–89%：可比较
- 60%–79%：近似产品
- <60%：排除

任何 `HARD` 约束失败都应单独记录，不能被综合评分抵消。

## 5. TCO 标准化

```text
采购总成本 = 商品金额 + 运费 + 税费 + 定制费 + 打样费
           + 模具费 + 包装费 + 支付手续费 - 数量折扣

标准化含税到手单价 = 采购总成本 / 实际采购数量
```

未知费用必须保留为未知，不能按零处理。币种换算需记录汇率来源和时间。

## 6. 供应商评估

产品比较与供应商比较分开。供应商维度包括企业主体、工厂或贸易商、经营年限、发票能力、认证、交易记录、评价、定制及打样能力、交期、售后和风险信号。

## 7. 综合评分

初始建议权重如下，实际项目可由采购经理调整：

| 指标 | 权重 |
|---|---:|
| 产品匹配度 | 25% |
| 实际采购价格 | 25% |
| 供应商可靠度 | 15% |
| 交期 | 10% |
| MOQ | 5% |
| 销量或交易记录 | 5% |
| 用户评价 | 5% |
| 发票或付款条件 | 5% |
| 售后保障 | 5% |

## 8. 输出

输出分三层：

1. 采购结论：搜索范围、候选数量、淘汰原因和建议优先询价对象。
2. 核心比价表：平台、供应商、商品、匹配度、MOQ、展示价、税费、运费、TCO、交期、供应商类型、评分及链接。
3. 采购证据：来源 URL、采集时间、原始字段、页面证据、可信度和待确认事项。

字段可信度使用 `HIGH`、`MEDIUM`、`LOW`、`UNKNOWN`。
