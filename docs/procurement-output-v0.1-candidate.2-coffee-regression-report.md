# 咖啡饮料机案例回归报告

## 结论

`procurement-output-v0.1-candidate.2` 能承载真实候选、价格梯度、优缺点、综合分、三种情景推荐、排除候选、风险、确认项和证据。案例文件通过 JSON Schema 校验，且保持 `READY_FOR_REVIEW`：四个阻断确认项未关闭，因此不能进入 `READY_FOR_APPROVAL`。

从采购判断看，GGM Gastro HAS2S 是当前综合平衡候选：含税约 297.49 欧元，页面标注欧洲免费配送，直接制作咖啡和热巧克力，使用机顶桶装水，并明确支持 230V/50Hz。Bosch TASSIMO 是最低购置成本方案；翻新 Nescafé Alegria 6/30 是较高产能方案；Sielaff Siamonie 因显著超出 1 万元预算被排除。

以上均为 2026-08-25 页面快照，不是锁价报价或采购承诺。

## 暴露的结构问题

### 1. `supplier_rating` 语义不足

真实页面同时存在产品评分、店铺评分、供应商评价和第三方客户满意度。candidate.2 只有一个 0—5 数字，无法表达评分对象、量表、评价数和来源。本案例只能将其留空，否则会把产品评分误写成商家评分。

建议改为 `ratings[]`，至少包含：`subject`、`score`、`scale_max`、`count`、`source`、`observed_at`。主表可按展示策略选择其中一个评分并标注类型。

### 2. 主表无法单独展示“商家评价不是数字”的情况

GGM Gastro 页面提供 TÜV Saarland 的“客户满意度 sehr gut”，但不能安全换算成 0—5。建议主表在数字评分之外允许 `supplier_signal` 文本摘要。

### 3. 评分可解释性只存在于自由文本

用户要求主表只显示总分是合理的，但当前各维度原始分只能写进 `score_explanation`。这样不利于复算和审计。建议在详细表增加机器可读的 `score_breakdown[]`，主表仍只显示 `overall_score`。

### 4. JSON Schema不能完成跨引用业务校验

candidate ID、detail ref、evidence ref、risk ref 的存在性与唯一性，以及评分权重合计100%，不能仅靠当前 JSON Schema可靠保证。冻结前需要增加业务校验脚本。

### 5. `READY_FOR_APPROVAL` 的充分条件仍偏弱

candidate.2 已能禁止开放的阻断确认项，但尚未强制要求推荐候选、非空总分、可比较总价及关键字段证据。建议在候选下一版补足这些条件。

## 冻结建议

本轮结论为“回归部分通过，不建议立即冻结”。应先形成 candidate.3，解决评分语义、评分明细和审批就绪条件，再用本案例复跑一次。采购需求本身仍缺少预计杯量、吧台尺寸/可用功率、具体送货地址以及供应商合规文件，这些是采购确认事项，不是 Requirement Schema 缺陷。
