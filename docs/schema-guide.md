# Procurement Requirement Schema v0.1 指南

## 设计目标

Schema 提供稳定采购骨架，同时允许不同品类通过属性约束扩展。它适用于标准品、定制品、设备与服务型采购需求，不把某一品类参数写死在顶层。

## 约束类型

- `HARD`：不满足即淘汰。
- `PREFERENCE`：影响排序，但不直接淘汰。
- `INFORMATION`：用于理解、展示或后续确认。

## 禁止静默假设

以下字段缺失时必须追问或明确标记未知：采购数量、交付期限、税率或含税口径、替代品牌许可、定制工艺。

## 补问策略

每轮最多提出三个阻断问题，优先级依次为：

1. 无法搜索或匹配的产品定义；
2. 数量、收货地和交付日期；
3. 会改变候选资格的硬规格、预算、税票、MOQ 或定制要求。

## Provenance

关键字段可在 `provenance` 中记录 JSON Pointer、来源类型、原始文本、记录时间和可信度。来源类型包括用户明确提供、附件、网页、推导和人工确认；推导值必须说明依据。

## 就绪状态

`readiness.blocking_questions` 非空时，状态通常应为 `NEEDS_CLARIFICATION`。只有数量、产品定义和搜索所需硬约束足够明确时，才进入 `SEARCH_READY`。
