# 最终采购输出结构 v0.1候选版

## 目标

输出应同时服务三类使用者：采购经理快速决策、业务或管理层内部审批、后续人员复核证据。

## 四层结构

### 1. 管理结论

- 搜索范围与覆盖情况；
- 是否形成推荐；
- 推荐候选和推荐理由；
- 最低成本、综合平衡、较高配置三种情景选择；
- 当前能否进入询价、审批或采购。

### 2. 核心比价表

每行代表一个“商品或服务候选＋供应商＋履约路径”。主要字段包括匹配度、硬约束失败、原始价格、标准化成本、未知费用、MOQ、交期、税票、供应商摘要、综合评分、证据及风险引用。

### 3. 风险与待确认

风险和待确认项分开：风险描述潜在影响，待确认项描述下一步需要谁回答什么。阻断项未关闭时不得进入正式推荐或采购审批。

### 4. 证据与审计

每个关键字段通过证据ID连接原始URL、采集时间、原始值、归一化值和可信度。报告保留需求版本、方法版本、假设、排除项及数据截止时间。

## 状态

- `INCOMPLETE`：尚无足够候选或证据。
- `READY_FOR_REVIEW`：可供采购经理初筛。
- `READY_FOR_APPROVAL`：阻断信息关闭，可提交内部审批。
- `FINAL`：人工决策已记录。

## 与后续Schema的边界

当前比价行保留Product Candidate和Supplier的展示快照及ID。后续定义两个独立Schema后，详细原始数据归其管理；最终输出继续引用ID并保留决策时快照，防止源数据变化导致历史报告不可复核。
