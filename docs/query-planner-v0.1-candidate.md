# Query Planner v0.1-candidate

## 状态

- 版本：`0.1-candidate`
- 状态：`DRAFT_FOR_HUMAN_REVIEW`
- 输入：Procurement Requirement。
- 输出：可执行的多平台搜索计划。

## 责任边界

Query Planner负责把需求展开为平台任务、关键词、筛选条件、访问策略、停止条件和失败降级规则。它不负责执行抓取、不判断商品是否合格、不计算评分，也不主动联系供应商。

## 核心规则

1. 用户指定平台使用 `MUST_SEARCH`；Agent补充的1—3个平台使用 `SUPPLEMENTAL_DISCOVERY`。
2. 每个平台独立生成符合当地语言和搜索习惯的关键词，不机械直译。
3. 硬约束若平台支持，使用 `PLATFORM_NATIVE`；不支持时转为 `POST_FILTER` 或 `MANUAL_REVIEW`。
4. 查询词分为核心品类、属性变体、使用场景、供应商发现、价格边界、合规和替代术语。
5. 访问受限时只能在已允许的方法间降级，并记录失败或跳过原因；不得声称未执行的任务已完成。
6. 停止搜索需要同时考虑合格候选数量、价格层级和必搜平台覆盖，不能只达到某个平台的数量目标就停止。
7. `SEARCH_READY` 且无阻断问题才能生成 `READY` 计划；否则计划必须标记为 `BLOCKED` 或 `PARTIALLY_EXECUTABLE`。
8. 未执行任务的 `execution_result` 为空；执行后必须记录尝试时间、结果数、详情数、结果说明和外部证据引用。

## 人工审阅重点

- 是否接受平台任务作为最小执行单元。
- 是否接受“平台内筛选”和“采集后筛选”显式分离。
- 是否接受每个平台有独立访问策略与降级路径。
- 是否接受停止条件同时约束候选数量、价格层级和必搜覆盖。
- 是否继续将主动询盘排除在Query Planner之外。
