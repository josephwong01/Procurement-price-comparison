# Procurement Price Comparison

面向企业采购场景的“选品与采购比价 Agent / Skill”。它既可以从开放需求中发现、筛选和评分候选产品，也可以对用户已经指定的商品或链接进行多平台价格比较，最终输出可追溯、供人工确认的采购结果。

## 两种工作模式

### 选品模式

适用于“帮我找适合的产品”“还有什么新奇产品可选”等开放式需求。流程是：冻结需求 → 提取关键词/方向 →（可选）公开趋势发现 → 建立候选池 → 按可调整权重评分 → 用户确认候选 → 进入多平台比价。

回归案例：2026 年德国慕尼黑电子展 JLCPCB 游戏互动 S+ 奖品。需求重点是科技感、新鲜感、外国用户可用性、人民币预算和展会场景适配度。

### 固定清单比价模式

适用于用户已经提供具体商品、型号、Item ID 或链接的场景。流程是：读取固定清单 → 多平台采集 → 规格与交易条件归一化 → 计算标准化到手成本 → 输出价格、供应商和风险比较。该模式不会自动扩展新的产品方向，除非用户明确要求。

回归案例：咖啡机多平台比价。输入是用户指定的咖啡机商品或链接，目标是比较价格、规格、库存、运费、税费、交期和供应商可靠度。

如果用户同时提出“先找产品，再比较价格”，先执行选品模式，待用户确认候选池后再执行固定清单比价模式。

## 当前状态

MVP v0.1 已完成：需求 Schema、最终输出、候选商品、供应商、Query Planner、匹配去重、TCO 评分、平台 Adapter 和 Skill 端到端组装均已冻结或完成回归。设备、标准品、定制品和服务类案例均已覆盖；最新盲测为“智能手环客户礼品”。

本版本止于候选比价和采购建议，不会自动联系商家、发送询价、下单、发起审批或写入 ERP。

## 核心流程

```text
选品模式：采购需求 → 补全与确认 → 方向/候选池 → 用户确认
         → 查询计划 → 多平台采集 → 归一化 → TCO/综合评分 → 输出

比价模式：固定商品/链接清单 → 查询计划 → 多平台采集
         → 规格与供应商归一化 → 到手成本比较 → 输出
```

## 快速使用

Skill 入口位于 `skills/procurement-sourcing/SKILL.md`。开始时先判断是选品模式、固定清单比价模式，还是两者串联。选品模式输入采购品类、数量、预算、用途、收货地和到货要求；比价模式输入商品名称、型号、Item ID 或链接。信息不完整时，Skill 会区分硬约束、偏好、假设和待确认项，并保留证据与未知项。

首次使用或更换工作区时，请先阅读 [Apify 连接常见问题](docs/apify-browser-console-faq.md)。配置 `APIFY_TOKEN` 不会自动创建 Apify MCP；若当前会话没有 Apify 工具，可直接在 Codex 内置浏览器登录 Apify Console 后运行 Actor。

## 校验

安装校验依赖后运行：

```powershell
python -m pip install -r requirements-validation.txt
python scripts/validate_mvp.py
```

统一校验会检查全部 JSON 文件、端到端清单、底层 Schema/业务校验器、Skill 包结构、敏感信息和发布必需文件。

## 使用原则

- 原始平台价格和人民币比较价同时保留，汇率可用有时间戳的大致参考值。
- 产品适配度与供应商可靠度分开评估，再合并为可解释的单一总分。
- 不满足硬约束的候选不得伪装成合格项；排除原因必须展示。
- 库存、运费、税费、交期等不能确认时必须标记未知或待询价，不得编造。
- 搜索执行成功不等于产生有效候选；原始结果与有效候选数量分别记录。
